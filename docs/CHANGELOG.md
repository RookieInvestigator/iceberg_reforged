## v5.8.9 — 2026-11-10 — 全文搜索真的能搜全文 · 拼音模糊层 · 筛选与搜索不再互相吞

### 修复

- **正文深处的词搜不到**：全文索引里 Fuse 的默认打分含「匹配起点」罚分（`score = 错误数/查询长度 + 命中起点/distance`，`distance` 默认 100、`threshold` 0.3），合起来等于「命中必须出现在每段被索引文本的前 30 个字符里」。中文正文没有空格，Fuse 按空白分词后整段 `desc` 是一个 token，于是第 30 字之后的正文永远命中不了——实测 78% 的正文字符在第 30 字之后（正文字数中位数 116），从描述尾部取样 444 条词条，旧配置只搜得到 2 条。现在显式关掉位置罚分，分数只看编辑距离。
- **标签一开，搜索整段失效**：筛选判定（`useFilterPipeline` 内的 `matchesFilter`）在标签分支提前 `return`，标签命中就不再看搜索命中集。实测标签「📜 史学」317 条 + 查询「才得以」得到 317 条（正确结果应为 1 条）。判定抽到 `lib/iceberg/filterMatch.ts`，各维度统一 AND，没有提前返回。
- **搜索 + 标签 / 收藏 / 隐藏分类 / 特殊档的组合统统按 AND 生效**，并有 `filterMatch.test.ts` 钉住（含「标签开启不吞搜索」这条回归用例）。
- **确认没有精确命中时不说「无结果」**：速查下拉原先在 Worker 还没回结果时也渲染「无结果」，现在只在「这条查询的结果已经回来」时才说（`suggestSettled`）。

### 改进

- **速查下拉不再自己建第二个 Fuse 索引**：命中改读 `wallState.searchHits`（词条墙的同一份 Worker 结果），两处永远一致；历史实现只索引标题/分类/标签，于是「正文命中的查询」会出现「下拉说无结果、墙上筛出几条」的自相矛盾。正文命中额外给一行摘要，说明它为什么会出现在结果里。
- **查询归一化**：全角↔半角（NFKC）、连续空白折叠、间隔号 `·・•‧∙⋅` 统一、小写。索引侧与查询侧都过同一道，`375·330` / `３７５・３３０` 都能找到「北京公交车375・330」。
- **多关键词按 AND 合并**：`水猴子 传说` = 两个词都命中（原来整串当一个模式，几乎搜不到）。
- **拼音模糊层（新增依赖 `pinyin-match`）**：精确层一条都没有时，标题按拼音全拼 / 首字母缩写 / 中英混合 / 带空格分词匹配（`shz`、`shuihouzi` 都能找到「水猴子」；支持多音字）。下拉显示「没有精确命中 · 以下是拼音/缩写模糊匹配」，命中计数加 `≈` 前缀，不把近似结果伪装成精确结果。
  - 选型对比：`lunr + lunr-languages`（CJK 用 `Intl.Segmenter` 切 bigram，`~1` 支持错字）体量更大且要换掉现有 Fuse；`FlexSearch` 有 CJK charset 但同样不做拼音；`pinyin-match` 是中文模糊搜索里最直接的一个（MIT、零依赖、自带类型、gzip ≈ 20KB），只补在 Worker 里。
  - 它**不做错字容错**（`水猴孑` 不会命中「水猴子」），这条边界写进了 `searchIndex.ts` 文件头和测试，不假装覆盖。
- 索引选项与检索逻辑全部收敛到 `lib/iceberg/searchIndex.ts`（Worker 只做消息收发），`searchIndex.test.ts` 覆盖：正文深处命中、全角/间隔号、多词 AND、拼音全拼/缩写、无关查询、标题模式隔离、空查询返回 null。
- **顶栏加了「精确 / 模糊」切换**（`filterStore.searchFuzzyMode`，默认模糊），紧挨着「全文 / 标题」，两者正交组合出四种检索范围：`全文·模糊` / `全文·精确` / `标题·模糊` / `标题·精确`。
  - **模糊 = 精确命中 + 拼音/缩写命中同列**（精确在前、按 id 去重，`exactCount` 记录精确层贡献几条）；不是「精确没命中才补」——用户明确选了模糊，就该两种结果都看到。
  - **精确 = 只认精确匹配**（`allowFuzzy: false`），拼音层整个不跑；零命中时下拉多一行「没有精确命中的词条 · 改用模糊搜索试试 →」，点一下即切到模糊并重搜同一关键词，不会只丢一句「没有匹配」。
  - 小屏（≤640px）顶栏放不下，两个开关一起收进筛选面板的「搜索」分组。
- **中文标题的「真·模糊」**（此前只有拼音层，标题写得不对就搜不到）：
  - 覆盖匹配：查询的字**不要求连续、不要求顺序**，每个字都得有着落——标题里有这个字，或有同声母的字顶替（`精→景`、`候→猴` 这类同音错字）。实测 `景人` / `景人国` / `精国人` 都能搜到「景国人粥」，且排第一。
  - 两字词不做同音顶替（「任一 J 声母字 + 人」会一发一大片，实测噪声 60 条），三字以上最多顶 1 个字；缺字一律不接受，避免精确查询被近似结果淹没（`水猴子` 仍只出 2 条，不会混进「小猴子」）。
  - 拼音层保留（纯字母查询：`shz` / `shuihouzi`），与覆盖层按查询形态二选一：含汉字走覆盖层，纯字母走拼音层。
  - 下拉提示相应改成「模糊匹配（同音 / 乱序 / 拼音）」。
- **搜索 Worker 改成惰性启动**：Worker 里装着 Fuse + pinyin-match + 拼音首字母表（gzip ≈ 45KB），首屏不该为「还没开始搜索」付这份体积。现在第一次输入非空查询时才建 Worker（实测首屏 0 个 worker 分片请求，输入后才 1 个），之后索引常驻、打字不走网络。
- **模糊标注分两种**：整批结果都是拼音近似时计数带 `≈`、提示「没有精确命中 · 以下是模糊匹配」；只有部分近似时提示「含模糊匹配，排在精确命中之后」，计数保持普通数字。
- 顶栏收拾干净：删掉多余的 `⌘K` 按钮（搜索框内已有 `/` 提示，键盘快捷键 `⌘K` / `/` 仍然可用），「模糊」按钮去掉悬停提示——开关本身就是自解释的，鼠标移上去弹一长条说明反而多余。
- **零命中不再被吞成「没搜索」**：命中结果是三态 —— `null` = 没搜 / `[]` = 搜了但零命中 / 非空 = 命中。先前的 `ids && ids.length ? ids : null` 把零命中折叠成「没搜」，于是精确模式下输入 `shz` 会显示全部 1461 条（实测 `1461 / 1461`）；现在零命中就是 `0 / 1461`，词条墙一条不显示，下拉显示「没有匹配的词条」。
- **页脚 / 页头加「星图」入口**为 DEV 页后，搜索与筛选的交叉验证：标签 317 → 标签 + 搜索 1 → 只搜索 4 → 清空 1461，逐档实测。

## v5.8.7 — 2026-11-07 — 让地址栏说实话

### 修复

- **打开词条后地址栏自带 `?trail=`**：这个参数是「显示探索轨迹」面包屑功能的产物，而该功能**默认关闭** —— 下面没有任何面包屑可看，地址栏却被填上一串 8 位 id。现在只有开关打开时才写，打开后也才从 `?trail=` 恢复；拖着带 `?trail=` 的旧链接进来、而开关是关的，会把参数洗掉且不弹任何词条（否则会在毫无提示的情况下跳到某个词条）。
- **hash 永远停在第一个词条**：原先 `#<id>` 只在首次打开时由深链写入，之后下潜三层地址栏还是 `#<第一条>` —— 复制出去指错人。现在每次打开/切换都把 hash 重写为当前词条（实测桌面下潜 3 层：hash 依次 `584259ec` → `71044be7` → `39c59fd5`；手机左滑切换同样跟着换）。关闭时清空。
- 切换「探索轨迹」开关时立即对齐地址栏，不用等下一次打开词条才生效；轨迹栈为空时不动，以免把 tooltip 模式下的深链 hash 抹掉。

## v5.8.6 — 2026-11-07 — 修掉分类页的加载遮罩与死锚点

### 修复

- **分类胶囊切换后「闪一下黑」**：加载遮罩原先在 `beforeEach` 就开始 0.55s 淡入，而站内一跳实测 465ms 就画好了 —— 遮罩亮到 84% 时新页面已经可见，观众看到的是「内容出来了 → 又盖一层黑 → 再淡出」。现在遮罩改为**延迟 600ms 才盖**（快跳转一帧都不闪）、盖上去时**瞬显不淡入**、只保留淡出，且就绪后取消尚未到点的「盖上」。顺带修掉定时器里 `if (shieldHidden) return` 写反导致**慢加载也永远不盖遮罩**的问题（重度节流实测 5.2 秒的跳转全程无遮罩）。
- 首页静态壳的 1461 个 `href="#<id>"` 是**死锚点**（页内没有任何对应 id）。这些锚点在客户端接管时本来就会被整块替换、也不承担导航，改为纯文本直出，锚点归零；真正的内链交给 15 条分类导航。分类页的词条标题则链回 `/#<id>`（跨文档，是站内唯一定位到单条的地址）。
- 分类页 tab 链接补尾斜杠（`/category/<slug>/`），与 canonical 一致，从地址栏复制后刷新不再吃一次 308。
- `noscript` 里写死的「收录 1454 词条」改为构建期从 `meta.json` 取真值（现为 1461），并把其中的「专题」入口换成「分类」。
- **词条弹窗「关闭时没有渐变」**：`BaseModal` 的 `<Transition>` 包着一个一直存在的节点，而 `v-if` 在父组件（`<V2EntryCard v-if="modalItem">`）上 —— 一 `emit('close')`，整个组件当场销毁，Transition 根本来不及播 leave，所以只有打开有淡入、关闭是硬消失。改成把 `v-if` 移进 `BaseModal` 内部（`shown`）、由 `@after-leave` 再抛 `close`；关闭点（X / Esc / 点遮罩）统一走 `requestClose`，另加 220ms 兜底（`prefers-reduced-motion` 关掉过渡时也要能关）。同时给过渡补上位移：打开「淡入 + 上浮 8px」、关闭「淡出 + 下沉 6px」，两条边对称。实测关闭 1.00 → 0.81 → 0.62 → 0.39 → 0.12 → 移除、translateY 1→5px；打开 0 → 0.17 → 0.32 → 0.71 → 0.89 → 1.00、translateY 8→0。
- 关闭过渡期间又点开别的词条时，`BaseModal` 会收到新的 `token`（词条 id）并撤销这次关闭 —— 否则 220ms 的兜底定时器会把刚打开的内容一起关掉。
- **路由切换后不回到页首**：`router` 原先没有 `scrollBehavior`，浏览器保持原 `scrollY` —— 在 34000px 高的分类页滚到底点另一个分类，新页面直接停在 33405px，看到的是中段（实测）。现在统一回顶部，三条例外：浏览器前进/后退用 `savedPosition` 还原原位置、`to.hash` 交给词条深链弹窗、只换查询串（同 path）不动滚动。
- **移动抽屉关闭时内容先没了**：与弹窗同一个毛病 —— 父级把 `item` 置 null，面板 `<template v-if="item">` 当场清空，0.35s 里滑走的是一条空壳。现在面板自己留一份最后渲染的词条（`rendered`），等下滑走完再清。
- **切换词条后停在原滚动位置**：滑动/键盘切到下一条时面板与弹窗都是同一个 DOM，浏览器把上一条的 `scrollTop` 原封不动带过去 —— 实测滚到 197px 切过去，新词条开头在视野外。抽屉与 `BaseModal` 都在内容标识变化时把滚动位置归零。
- **移动抽屉第一次打开不锁背景滚动**：`useSheetShell` 的 `watch(open)` 没带 `immediate`，而抽屉是首次打开那一刻才挂载的，挂载时 `open` 已经是 `true` —— 这次变化收不到，实测第一次打开背景照样能滚 500px，第二次起才正常。同时 `V2Sheet` 的滚动测量 watch 也补了 `immediate`，`canScroll` 否则永远是 `false`。
- 抽屉底部「下面还有内容」的渐隐遮罩（`.sheet-fade`）**自上线起就没有样式**（模板里有节点、任何 CSS 都没定义过，`display:none`）。补上 40px 的向上渐变，用渐隐而不是叠半透明层，避免把正文压暗。

### 改进

- 首页与分类页的标题列表改成**一行一条**：deflate 的 32KB 历史窗口在一条超长行里会不断滚动而错开同位置结构，换行后每行重复前缀落在窗口内同一偏移。首页 HTML 从 138268 字节降到 52713 字节，gzip 从 42.2KB 降到 **28.6KB**（正文其实更完整了 —— 原先靠一堆重复的 ` · ` 分隔符撑起来）。
- `/features/` 移出 `sitemap.xml`（21 条）：唯一一篇 `000-placeholder.md` 是演示样例，被 `PLACEHOLDER_SLUG` 过滤后列表页只剩「暂无专题文章」254 字，属薄内容。等有真实专题再加回。

## v5.8.5 — 2026-11-07 — 让全站正文有真实 URL

### 新增

- 15 个分类聚合页（`/category/<slug>/`，slug 见 `lib/iceberg/categorySlug.ts`）：把每个分类下**全部词条的标题、层级、标签、正文**直出成静态 HTML。此前 1461 条正文只存在于 JS 数据里，爬虫拿到的是空壳；现在它们全部有可索引的 URL，且不是一个词条一页（那要 +15MB、构建慢几十倍），而是 15 页承载 1429KB → 优化后 991KB。分类归属用 `itemCategories()` 取装配后的多分类，所以副表 `categories.csv` 追加的副分类词条不会漏（实测 `folklore` 201 条 > 原始分类 195 条）。
